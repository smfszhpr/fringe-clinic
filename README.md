# 临界诊室开发版

当前诊室使用四职责时间线架构，直接提交行动、缓存未来病程、按采集时点回报检查，并通过“出院并结束本局”生成后日谈。新接口、离散时间近似和验证说明见 [TIMELINE.md](TIMELINE.md)。下文的 plan/action/outcome/finish 仍用于旧评测入口，新诊室使用 submit/advance/simulation/discharge。

## 整局评测

`cases/playthroughs.json` 的每条记录覆盖接诊、逐轮操作和结局，包含每轮期望、最终状态及关键证据应出现的轮次。运行 `python evaluate_playthroughs.py`，或用 `--case direct-correct-care` 只跑一局。默认启动使用临时数据库的本地 HTTP 服务。结果逐局写入 `results/playthroughs.json`。

评测依次调用 `POST /api/start`、`/api/plan`、`/api/action`，按需调用 `/api/outcome`，最后调用 `/api/finish`。后两个接口接收会话 ID。前者检查进度，后者锁定结局。周明远病例只有在诊断有证据、处置已实施、且处置后另有一轮客观复评支持改善与后续监护时才记为 `treatment_complete`。其他患者暂未配置结局标准。

报告区分预期不符和接口报错。逐轮语义评审使用同一模型的独立提示词，适合查找回归，不能代替人工核验。当前标准用于虚构游戏结局。

入口 `/` 为患者选择页；接诊后进入 `/clinic`。固定病例资料位于 `cases/patients.json`，包含公开入院病历、病人本人知道的病史与服务端隐藏病因三层。初始状态来自病例文件，之后的病程变化由模型推演。诊室中的“查看病历”“病史与用药”“患者信息”可随时查阅入院记录。三例为原创虚构剧情病例，尚未经医学专业审阅。

Python 3.12，无第三方运行依赖。将 `.env.example` 复制为 `.env` 并填写模型配置，执行 `python server.py`，访问 http://127.0.0.1:8765 。执行 `python evaluate.py` 运行六种病例、每例四轮的模型实验，结果保存在 `results/report.json`。模型评审与被测模型相同，不构成独立医学有效性证明。

打开方式：双击 `start.cmd`，保持服务窗口运行，然后在浏览器打开 http://127.0.0.1:8765 。目录链接是源码位置，不是网页入口。
